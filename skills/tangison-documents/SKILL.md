# Tangison Documents

## Purpose

Produce accurate, editable, print-ready formal documents that preserve exact facts, authentic logos, legal wording, and complete page content.

**A completion claim without evidence is invalid.**

## Use this skill when

- A transactional or formal business document is required.
- A supplied template or government form must be preserved.
- A DOCX or PDF must be rendered and inspected.

## Do not use this skill when

- Do not invent legal, financial, registration, contact, tax, or payment details.
- Do not change official form wording or structure without authority.
- Do not use magazine styling when formal clarity is the owner.

## Ownership

This skill owns formal document structure, layout, and rendering. Business Plan and Financial Model own their reasoning and figures.

## Required inputs

- Exact document type, audience, purpose, page size, and format.
- Authentic logos, client details, exact wording, figures, dates, and signatures policy.
- Source template and required editable format.
- Approval and verification items.

## Inputs to inspect first

1. Read the complete current request.
2. Read approved project files and authentic source assets.
3. Read repository instructions and inspect the current state when code or files are involved.
4. Read **BUILD_PLAN.md** and **PROOF.md** when present.
5. Inspect available capabilities before declaring a tool or check unavailable.

## Assumptions and authority gates

- Stop when legal meaning, signatory, registration, banking, tax, amount, or official wording is unclear.
- Do not alter photographed government evidence; restoration must preserve content.
- Record every material assumption. Never present an assumption as a verified fact.
- Ask one concise question only when the answer materially changes scope, ownership, legal meaning, cost, public release, production state, or an irreversible action.
- Never expose credentials or place them in source, URLs, logs, evidence, or handoff files.

## Required tools and fallbacks

- Use editable DOCX or deterministic document source when possible.
- Render every page to images or PDF for visual inspection.
- Verify arithmetic and tables against machine-readable source data.
- When a required capability is unavailable, use the nearest safe supported method and record the missing verification.
- Never invent a tool result, browser result, build result, deployment result, or remote state.

## Procedure

1. Create a fact and exact-text ledger.
2. Inspect the authentic logo and source template.
3. Define page size, margins, grid, hierarchy, typography, tables, folios, and signature handling.
4. Build the complete editable document.
5. Preserve exact approved wording and figures.
6. Render every page.
7. Inspect every page for clipping, overflow, missing content, incorrect page order, broken tables, weak contrast, and inconsistent branding.
8. Recalculate totals and percentages outside the layout.
9. Correct defects and rerender the affected and adjacent pages.
10. Export final editable and PDF files when requested.
11. Record page-level proof.

## Verification

- All required pages exist in correct order.
- Exact text, names, dates, amounts, contact details, and logos match source.
- No clipping, overflow, missing glyph, or broken table remains.
- Arithmetic and financial figures reconcile.
- Print size and margins are correct.
- Every page was rendered and inspected after the latest change.
- Run verification after the latest material change.
- Separate action, observed result, evidence, interpretation, and remaining risk.

## Proof requirements

Maintain **PROOF.md** for material work using:

Phase | Action | Target | Command or method | Result | Evidence path or URL | Timestamp | Status

Use only these working statuses: planned, running, passed, failed, blocked, paused, superseded.

The following are not proof: a file merely existing, a claim that work should function, a check run before the latest change, a local commit without remote verification, or a different test replacing the failed test.

## Failure and debugging procedure

1. Reproduce the failure with the same input and command or method.
2. Preserve the failing output and evidence path.
3. Identify the root cause. Do not replace diagnosis with a guess.
4. Apply the smallest complete correction within the authorised scope.
5. Rerun the exact failed check, then run the relevant regression checks.
6. Record the failure, correction, new result, and remaining risk in `PROOF.md`.

## Completion gate

Do not claim completion until:

- every approved output exists and matches the locked scope;
- the latest applicable checks pass;
- **PROOF.md** contains real evidence;
- unauthorised or unrelated work is absent;
- remaining risk and blocked checks are disclosed.

## Handoff

Return editable source, final PDF when requested, exact-text ledger, page count, arithmetic checks, render evidence, and signature or legal items.
