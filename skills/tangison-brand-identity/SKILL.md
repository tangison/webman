# Tangison Brand Identity

## Purpose

Produce an organisation-specific, editable identity that is geometrically inspected and works across real print and digital sizes.

**A completion claim without evidence is invalid.**

## Use this skill when

- A new logo or identity is requested.
- An authorised raster mark must be faithfully reconstructed.
- Existing identity variants and usage rules are incomplete.

## Do not use this skill when

- Do not deliver a final official logo as raw image-model output.
- Do not redraw an existing official logo without explicit authority.
- Do not change a client logo during unrelated work.

## Ownership

This skill owns the logo and identity system. Vector Graphics supports path construction. Image generation may support mood exploration only.

## Required inputs

- Exact approved name and spelling.
- Brand attributes, audience, category, geography, applications, and constraints.
- Authentic existing marks and competitor or category references.
- Required variants and export formats.

## Inputs to inspect first

1. Read the complete current request.
2. Read approved project files and authentic source assets.
3. Read repository instructions and inspect the current state when code or files are involved.
4. Read **BUILD_PLAN.md** and **PROOF.md** when present.
5. Inspect available capabilities before declaring a tool or check unavailable.

## Assumptions and authority gates

- Stop when naming, trademark risk, ownership, or reconstruction authority is unresolved.
- Do not fabricate brand history or meaning.
- Record every material assumption. Never present an assumption as a verified fact.
- Ask one concise question only when the answer materially changes scope, ownership, legal meaning, cost, public release, production state, or an irreversible action.
- Never expose credentials or place them in source, URLs, logs, evidence, or handoff files.

## Required tools and fallbacks

- Use deterministic typography and vector paths for final marks.
- Use reference-led research and anti-slop review.
- Inspect SVG geometry, print output, favicon size, monochrome, and light and dark applications.
- When a required capability is unavailable, use the nearest safe supported method and record the missing verification.
- Never invent a tool result, browser result, build result, deployment result, or remote state.

## Procedure

1. Lock the exact name and descriptor.
2. Create a reference ledger without copying protected expression.
3. Define brand attributes and one identity idea.
4. Choose wordmark, symbol, monogram, or combination based on application needs.
5. Construct geometry and typography deterministically.
6. Define palette and contrast.
7. Create relevant primary, horizontal, stacked, symbol, wordmark, monochrome, reversed, favicon, social avatar, SVG, and transparent PNG variants.
8. Define clear space, minimum sizes, prohibited uses, and export naming.
9. Test spelling, geometry, monochrome, favicon, light, dark, screen, and print.
10. Run anti-slop and competitor-distinction review.
11. Record source and proof.

## Verification

- Exact spelling and geometry pass.
- Final logo is editable vector or deterministic typography.
- Monochrome, favicon, light, dark, and print tests pass.
- No generic swoosh, spark, bevel, faux 3D, unreadable detail, or accidental gradient remains.
- The mark is distinct from inspected competitors.
- Run verification after the latest material change.
- Separate action, observed result, evidence, interpretation, and remaining risk.

## Proof requirements

Maintain **PROOF.md** for material work using:

Phase | Action | Target | Command or method | Result | Evidence path or URL | Timestamp | Status

Use only these working statuses: planned, running, passed, failed, blocked, paused, superseded.

The following are not proof: a file merely existing, a claim that work should function, a check run before the latest change, a local commit without remote verification, or a different test replacing the failed test.

## Failure and debugging procedure

1. Reproduce the failure with the same input and command or method.
2. Preserve the failing output and evidence path.
3. Identify the root cause. Do not replace diagnosis with a guess.
4. Apply the smallest complete correction within the authorised scope.
5. Rerun the exact failed check, then run the relevant regression checks.
6. Record the failure, correction, new result, and remaining risk in `PROOF.md`.

## Completion gate

Do not claim completion until:

- every approved output exists and matches the locked scope;
- the latest applicable checks pass;
- **PROOF.md** contains real evidence;
- unauthorised or unrelated work is absent;
- remaining risk and blocked checks are disclosed.

## Handoff

Return identity rationale, authentic source, master files, variants, usage rules, test evidence, and unresolved trademark or legal items.
